# Data pipeline

Meigen Sports keeps original sources on DS1, uses the existing Turso database for curation, and serves reviewed static files through GitHub Pages. An npm installation also has typed offline records. Reading a public quote does not query DS1 or Turso.

The reviewed source inputs have 30 quotations (22 Gutenberg excerpts and 8 Wikiquote sports lines) and 1052 published dated history rows (10 same-event duplicates merged) in the bundled feed. They cover 142 month-days, leaving 224 gaps. The separate on-this-day fact feeds hold 103,592 facts that cover all 366 days. The longer-term feed should draw primarily from SPX's existing historical facts on DS1; source-verified open data supplements those facts. A source's data rights remain distinct from the package's MIT code licence.

## 1. Rebuild and verify

```sh
pnpm data:check
```

That compares every generated byte against committed source inputs. To compare all accepted records against the original private source files, set `MEIGEN_RAW_DIR` to the authorized local archive directory and run:

```sh
node scripts/data-verify.ts --raw-root "$MEIGEN_RAW_DIR"
```

Every quotation must match the original text at its cited line range. Every historic date must match the precise original structured statement or match row. Publication year is not an utterance date; event start is not necessarily an opening ceremony. No quote date, career debut, birthday, record or identity match is invented.

## 2. Archive original bytes and back them up

```sh
python3 pipeline/manual.py ds1-load --raw-root "$MEIGEN_RAW_DIR"
```

This is a dry-run: it checks 99 raw source files and constructs the planned SQL without opening a database connection. Set only the authorized `MEIGEN_DS1_*` connection environment; credentials are never read from a file or printed.

John supplies the authorized DS1 connection and approved Dropbox archive/export location. Once supplied, this one command enables verified backup and additive archival/loading:

```sh
python3 pipeline/manual.py ds1-load --raw-root "$MEIGEN_RAW_DIR" --backup-root "$MEIGEN_BACKUP_DIR" --apply
```

Backup files are create-only and hash checked before curated loading. Original bytes are added to **the existing `legacy_files.raw_archive`** with immutable `meigen/<sha256>/<filename>` names, so the existing DS1 backup/export monitoring sees them. A collision with different data fails without overwriting anything. Project-specific `legacy_meigen` tables map hashes and retrieval metadata to that central archive; they are not a parallel raw-byte store. Candidate records and immutable dataset snapshots live in the separate `meigen` schema. No existing sports table, role or release is modified.

## 3. Transfer archive-backed candidates to Turso

```sh
python3 pipeline/manual.py ds1-export --out candidate-export.json --apply
```

The output is a controlled local transfer file containing only the declared public candidate records and archive/hash evidence. Repeating the command accepts an identical existing file; a different file is never overwritten. Store this transfer file outside Git.

With the existing Turso URL and token supplied in the authorized `MEIGEN_TURSO_*` environment, load candidates manually:

```sh
python3 pipeline/manual.py turso-load --input candidate-export.json --apply
```

The import is transactional and idempotent. It creates only prefixed supplementary tables, preserves existing review decisions and rejects replacing an immutable version. It approves no records. A source correction requires a newly archived dataset version.

## 4. Review, export and publish

A reviewer checks attribution, exact text/facts, dates, identity links and source rights, then records an explicit approval and nonempty reviewer name for every accepted Turso row. The helper does not supply or impersonate that review.

```sh
python3 pipeline/manual.py turso-export --out reviewed-export.json --apply
```

This fails if any candidate is unapproved, lacks a named review, has changed since its archived hash, or the version is incomplete. It outputs a `FeedShard` without credentials, database URLs, review names or raw source bytes. An excluded row is handled in a new reviewed dataset version, not by quietly truncating an existing version.

The current static source inputs rebuild with `pnpm data`. Compare the reviewed Turso export to the accepted source records, prepare the next dataset version, regenerate and run all package gates before the usual manual release process. No pipeline helper commits, pushes, tags, publishes npm, changes Pages or schedules a recurring run. No helper contacts Supabase.

Versioned static files use `data/v1/<dataVersion>/`: `all.json`, `quotes.json`, `history.json`, `days/<MM-DD>.json`, `sports/<sport>.json` and `entities/<base64url-UTF8-ID>.json`. `manifest.json` records every shard's checksum, size and record count plus actual calendar gaps. Missing days stay missing; consumers may choose a properly labelled general-sport quote fallback.

The initial archive and candidate load **completed on DS1 on 2026-10-15**: 99 raw source retrievals, 95 distinct raw hashes and 184 candidate records. Stored byte hashes and a complete DS1 export were verified. Hash-verified copies are in the existing local Dropbox raw-backup folder; remote synchronization was not independently confirmed. **Turso load, review and export remain pending and untested against its server**. Archival does not grant publication approval. Full environment variables, SQL assets, review requirements and offline commands are in the [manual pipeline reference](../pipeline/README.md). Source licences and original notices are in [source data](../data-sources/README.md) and [credits](../LICENSES/GUTENBERG-CREDITS.md).

## 5. People of every sport, from the Wikidata dump

The one-off Wikidata dump of 2026-10-12 (CC0, 156 GB compressed) was filtered on nas1 by spx-stats' `scripts/wikidata_dump/filter.py` into sports people, events, items and labels, and loaded on DS1. This package reads the filtered files, read only, and never the dump itself and never the network:

```sh
python3 -I pipeline/wikidata_dump_people.py --report   # counts only, writes nothing
python3 -I pipeline/wikidata_dump_people.py            # writes extract_wikidata_dump_people.json to MEIGEN_EXTRACT_DIR
python3 -I pipeline/convert_extract.py                 # reads it with the other extracts
pnpm data && python3 -I pipeline/coverage_people.py
```

`MEIGEN_WIKIDATA_DUMP_DIR` names the folder of the filtered files and `MEIGEN_WIKIDATA_OCCUPATIONS` spx-stats' `occupations.tsv`. The extract holds each birth and death with its Q id, a sport, an ISO nationality code and an `epithet`, plus the dump's name, date and hashes, which the converter copies into `facts/manifest.json` (`sources.wikidataDump`) with the count it added. The rules (a sports person, day precision, the Gregorian calendar, from 1850, never January 1, fame by Wikipedia editions with a per-day-and-sport floor, words from data, nothing about sex, gender, ethnicity, religion, politics, family or health) are in the header of `pipeline/wikidata_dump_people.py` and each has a count in its report; 44,922 births and deaths in 146 sports were added, by sport and by day in [coverage of people](coverage-people.md). `pipeline/test_wikidata_dump_people.py` and `test/dump-people.test.ts` hold the rules.

## 6. Events of every sport, from the same dump

The dump's events (competitions, games, finals, races, bouts, Games) take the same road, with `pipeline/wikidata_dump_events.py`, `extract_wikidata_dump_events.json` and the same provenance (`sources.wikidataDumpEvents` in `facts/manifest.json`):

```sh
python3 -I pipeline/wikidata_dump_events.py --report
python3 -I pipeline/wikidata_dump_events.py
python3 -I pipeline/test_wikidata_dump_events.py
python3 -I pipeline/coverage_events.py     # docs/coverage-events.md
```

An edition with a start and an end is two facts (`competition-start`, `competition-end` with its winner), a single day one (`sport-event`). A season, a play-off, an edition of a league SPX holds, para sport, a date on January 1 or December 31 and an end before its start are left out; the place and the winner are the item's own; the winner who is a person is not named where the event's name carries a sex marker, and a national team is named by its country. 28,205 events in 185 sports were added, by sport and by day in [coverage of events](coverage-events.md); `test/dump-events.test.ts` holds the rules.

## Older sources remain useful

A fixed old edition or historical corpus is a valid snapshot when its rights and provenance are verified. Each citation carries `snapshot.status`, pinned revision and actual capture time; exact history coverage is included when known. An old commit does not prove its source is discontinued, and a working URL does not prove it is maintained. Book publication years do not become invented coverage dates.

Choose source providers independently from history categories: `includeSources` and `excludeSources` use source IDs; `types` and `excludeTypes` choose record types. No library rule automatically drops an inactive source. Source lifecycle, underlying text/data rights and human publication approval remain three separate facts.

## From the README's Architecture section

The package separates TypeScript code, bundled JSON and source material. Raw source bytes are stored in the permanent DS1 archive; the 99 retrievals and 95 unique archive hashes have been verified against stored bytes, and local Dropbox backup copies have been verified. Turso curation and public release remain pending, and remote Dropbox sync is unconfirmed. Public readers use versioned static JSON.
