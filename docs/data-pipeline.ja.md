# データパイプライン

Meigen Sports は、原資料を DS1 に保存し、既存の Turso データベースで選別・確認し、審査済みの静的ファイルを GitHub Pages で公開します。npm パッケージにはオフラインで使える型付きデータも含まれます。利用者が公開フィードを読むとき、DS1 や Turso には接続しません。

確認済みデータには、引用が30件（Gutenberg の抜粋22件と Wikiquote のスポーツ8件）、公開する日付の出来事（同梱フィード）が1052件あります（同じ出来事の重複10件を一つにまとめました）。同梱フィードは366日のうち142日をカバーし、224日は未収録です。別の「過去の今日」の事実フィードには103,592件があり、366日すべてをカバーします。長期的には SPX の DS1 にある歴史データを中心にし、権利を確認した公開データを補足として使います。データの利用条件は、パッケージコードの MIT ライセンスとは別です。

## 1. データの再生成と照合

```sh
pnpm data:check
```

生成済みファイルと入力データが一致するか確認します。原資料と全レコードを照合するには、認可されたローカル資料フォルダーを `MEIGEN_RAW_DIR` に設定し、次を実行します。

```sh
node scripts/data-verify.ts --raw-root "$MEIGEN_RAW_DIR"
```

引用文はすべて、指定された原資料の行と照合します。歴史上の日付は、構造化された記述または試合データと照合します。出版年を発言日として扱わず、競技期間の開始日を開会式の日付と決めつけません。引用の日付、選手のデビュー、誕生日、記録、人物同一性を推測で追加しません。

## 2. 原資料を DS1 に保存し、バックアップする

```sh
python3 pipeline/manual.py ds1-load --raw-root "$MEIGEN_RAW_DIR"
```

このコマンドは初期状態ではドライランです。原資料99ファイルを確認し、接続や書き込みを行わずに予定 SQL を作成します。認可済みの DS1 接続情報は `MEIGEN_DS1_*` 環境変数で渡します。認証情報をファイルに保存したり、表示したりしません。

John が認可済み接続と承認済み Dropbox 保存先を指定した後、バックアップと追加保存を行うコマンドは次のとおりです。

```sh
python3 pipeline/manual.py ds1-load --raw-root "$MEIGEN_RAW_DIR" --backup-root "$MEIGEN_BACKUP_DIR" --apply
```

バックアップは既存ファイルを上書きせず、新規作成後にハッシュを検証します。原資料のバイト列は、DS1 に既にある `legacy_files.raw_archive` に `meigen/<sha256>/<filename>` という変更不能な名前で登録します。そのため既存の DS1 バックアップ・エクスポート監視の対象になります。異なる内容との名前衝突は失敗し、上書きしません。プロジェクト固有の `legacy_meigen` 表にはハッシュ対応と取得履歴を、`meigen` スキーマには候補データと変更不能な版スナップショットを保存します。既存のスポーツ表、権限、リリース記録は変更しません。

## 3. アーカイブ済み候補を Turso に移す

```sh
python3 pipeline/manual.py ds1-export --out candidate-export.json --apply
```

出力は、公開予定の候補データとアーカイブ・ハッシュの根拠だけを含む、ローカルの受け渡しファイルです。同じ内容なら再実行できますが、異なるファイルを上書きしません。Git 管理外に保管してください。

既存 Turso の URL とトークンを認可済み `MEIGEN_TURSO_*` 環境変数で渡し、手動で読み込みます。

```sh
python3 pipeline/manual.py turso-load --input candidate-export.json --apply
```

読み込みはトランザクション内で行い、同じ入力は再実行可能です。補助テーブルのみを作成し、既存の審査結果を維持し、変更不能な版の差し替えを拒否します。候補を自動承認しません。原資料の修正は新しいアーカイブ版として取り込みます。

## 4. 審査、エクスポート、公開

審査担当者が帰属表示、本文、日付、人物・チームの識別、出典の利用条件を確認し、採用する各 Turso 行に明示的な承認と担当者名を記録します。補助ツールが担当者を装ったり、自動承認したりすることはありません。

```sh
python3 pipeline/manual.py turso-export --out reviewed-export.json --apply
```

未承認、担当者名なし、アーカイブ時のハッシュから変更された行がある場合、または版全体が揃っていない場合は失敗します。出力には `FeedShard` 形式で承認済みデータを含め、認証情報、データベース URL、担当者名、原資料のバイト列は含めません。除外する行がある場合は、新しい審査済み版を作ります。変更不能な版から黙って行を取り除きません。

現在の静的データは `pnpm data` で再生成します。Turso の審査済み出力を元データと比較し、採用行を次の版に反映してから再生成し、パッケージの全チェックを通して通常の手動リリースを行います。補助ツールはコミット、プッシュ、タグ作成、npm 公開、Pages 更新、定期実行を行いません。Supabase にも接続しません。

版管理された静的ファイルは `data/v1/<dataVersion>/` にあります。`all.json`、`quotes.json`、`history.json`、日付別、競技別、安定したエンティティ ID 別のシャードを含みます。`manifest.json` は各ファイルのハッシュ、サイズ、件数と実際のカレンダー欠落日を記録します。存在しない日を埋めません。

2026年10月15日、DS1 への初回アーカイブと候補データの読み込みが完了しました。取得履歴99件、異なる原資料ハッシュ95件、候補レコード184件を保存し、保存されたバイト列のハッシュと全件の読み戻しを検証しました。既存のローカル Dropbox 原資料フォルダーにもハッシュ確認済みのコピーがありますが、リモートへの同期完了は独立に確認していません。Turso への読み込み、審査、エクスポートは未実施で、実サーバーでの動作も未検証です。アーカイブ保存だけでは公開承認になりません。詳しい環境設定、SQL、審査条件は[手動パイプライン手順書](../pipeline/README.md)と[原資料一覧](../data-sources/README.md)を参照してください。

## 古い版の原資料も利用できる

権利と出所を確認できる固定版や歴史資料は、有用なスナップショットになります。各引用には、取得時点で確認した状態、固定リビジョン、実際の取得日時を記録します。根拠がある場合は日付範囲も記録します。古いコミットだけでは提供元が停止したとは言えず、URL が応答するだけで保守中とも言えません。本の出版年からデータの対象期間を作りません。

利用する提供元と履歴の種類は別々に選べます。`includeSources` と `excludeSources` は提供元 ID、`types` と `excludeTypes` は記録種別を指定します。提供元が停止したことだけを理由に、ライブラリが履歴を自動除外することはありません。提供元の状態、原資料の権利、公開前の人手審査は別々に管理します。
