This guide is the map for someone who wants to change the package or to know why it behaves as it does. [How the data is built](how-the-data-is-built.md) says where the facts come from; this one says where they live, how a call reaches them, and what keeps the answers the same everywhere.

## Three things, kept apart

```text
src/            the code: pure functions, typed, no data of their own
src/data/       what ships in the package: 1,525 offline facts, 30 quotations, a history starter
data/v1/<v>/    what is published on GitHub Pages: 126,810 facts in static JSON, with a catalogue
```

- **The code** (`src/`) reads records and returns records or strings. It reads no file and no network unless you hand it a `fetch`.
- **The package's data** (`src/data/`) is small on purpose: about 1 MB packed. The `offline` entry is the best three to five facts of each of the 366 days, chosen by significance and fame and varied by kind, sport, person and club.
- **The feed** (`data/v1/<version>/`) is every fact, in shards by day, sport and entity, validated by the `load*` functions. A site reads it when it can, and falls back to the offline set when it cannot, and says that it did.

One build makes both, and `node scripts/check-build.ts` fails a release when the package and the Pages site are not the same build: it compares the package version, the data folder and a SHA-256 of the facts manifest.

## The path from a date to a sentence

```text
a date ──► dates.ts ──► facts.ts ──► sentences.ts (templates/) ──► display.ts ──► HTML
 "11-20"   month-day     which facts    a fact worded for the day    four layouts
            or full date  match, ranked   it is read on, in a language  (calendarIcon beside)
```

- **`dates.ts`** reads a date. `YYYY-MM-DD` is an exact date and `MM-DD` a calendar day; an exact date also excludes later records. No function here reads the clock: `calendarDayInZone(timeZone, nowIso)` answers "what day is it there" from a moment you pass.
- **`facts.ts`** selects and ranks: by day, sport, entity, source, kind, language and text. `significance` and `rankFeed` order a feed, with caps so that no sport or club fills a day.
- **`sentences.ts`** and `templates/` word a fact. The sentence is made from the fact's fields by committed templates; if a field is missing the template is skipped, so the package says less rather than guess. `renderRun` words a list so that neighbours never repeat.
- **`display.ts`** and **`calendarIcon.ts`** draw the result: four layouts of HTML and eighteen calendar pages as SVG. Both are pure.

```js
import { factsFor, renderRun } from "@johnmorrisdotca/meigen-sports";
import offline from "@johnmorrisdotca/meigen-sports/offline";

const facts = factsFor(offline, { date: "10-20" }).slice(0, 3);
const a = renderRun(facts, { seed: "card", locale: "en", asOf: "2026-10-20" });
const b = renderRun(facts, { seed: "card", locale: "en", asOf: "2026-10-20" });
console.log(a.length > 0, JSON.stringify(a) === JSON.stringify(b));
```

## Rules

1. **No clock and no randomness.** The date, the time zone and the seed are arguments. The same call gives the same answer in Node, Deno, Bun, a worker and a browser, and a server can draw the card a browser draws.
2. **Provenance travels with the row.** Every fact and quotation carries its source, its licence and a link to the original. The MIT code licence does not relicense the data; the rights are in `NOTICE.md` and `data-sources/`.
3. **Never invent a date.** A quotation has no utterance date and is never given an anniversary. A publication year is not a date; an event's start is not an opening ceremony. A fact is only what the source says.
4. **The loaders validate.** The `load*` functions take your `fetch`, check what comes back against the schema and refuse what does not fit, so caching, retries and cancellation stay yours and a bad feed does not reach the page.
5. **Text is escaped on the way out.** `displayMarkup` escapes every fact's text, so its string can be set as HTML.

## The entries

| Entry | What it holds |
| --- | --- |
| `@johnmorrisdotca/meigen-sports` | the selectors, the sentences, the calendar pages and the layouts |
| `/offline` | the bundled on-this-day facts |
| `/history`, `/quotes` | the history starter and the quotations |
| `/load` | the loaders for the published feed |
| `/categories`, `/catalogue.json` | the kinds of fact, and what is inside, counted by the build |
| `/styles.css` | the optional stylesheet for the layouts |

## How the data is made

The facts are built by `scripts/data.ts` and the python pipeline in `pipeline/` from source extracts that are archived, checksummed and verified: `pnpm data:check` compares every generated byte against committed source inputs, and `node scripts/check-golden.ts` holds the famous facts the data must contain. [Data pipeline](../data-pipeline.md) has the whole account.

## How it is kept true

| Check | What it holds |
| --- | --- |
| `pnpm check` | the shards, lint, types, the unit tests, the build and the packed package |
| `pnpm test:readme` | every example in the README, the docs and the guides, run against the built package |
| `pnpm test:usage` | every way of using the package that the guides show, built or run as npm packs it |
| `pnpm test:golden` | the famous facts are in the data |
| `pnpm test:demo` | the demo in a real browser at a phone's width and a desk's |
| `pnpm docs:check` | every export has a doc comment and a running example; every guide has its front matter and its links lead somewhere |
