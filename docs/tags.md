# Tags: what a fact is about, and how to ask for it

Generated by `python3 -I pipeline/coverage_tags.py` (`pnpm data:coverage-tags`). Do not edit the numbers by hand.

Every one of the 103,592 facts carries its tags in `tags`: the history types that say what kind of fact it is (`player-birthday`, `championship-win`; [the 46](./categories.md)) and the namespaced tags below, `namespace:value`, that say what it is about. The namespaced tags are not a second copy of the data: each is built from a field the fact already holds, by `derivedTags` (`src/tags.ts`), and nothing is guessed, so a fact with no country has no `country:` tag. `tagsOf` lists every tag of a fact; `factsFor` finds by them; the static files hold an index of ids for the ones a reader asks for most.

A tag's value is letters, digits, hyphens, dots and underscores. A country is an ISO 3166-1 alpha-2 code (`RO`), or the ISO 3166-3 code of a former country that has a flag in Hata (`SUHH` the Soviet Union, `DDDE` East Germany, `CSHH` Czechoslovakia, `YUCS` Yugoslavia); England, Scotland, Wales and Northern Ireland are `GB`. A person of two countries has both, and the flag (`flag`, a code a flag set draws) only when he represents one in sport or has one country. A state no code names (the British Raj, the Empire of Japan) is not guessed.

## Asking for them

In the code, with the facts you already hold (the offline set here):

```js
import { derivedTags, factsFor, flagOf, tagsOf } from "@johnmorrisdotca/meigen-sports";
import { offline } from "@johnmorrisdotca/meigen-sports/offline";

const fact = factsFor(offline, { tags: ["sport:baseball"] })[0];
console.log(tagsOf(fact).includes("sport:baseball")); // true
console.log(derivedTags(fact).every((tag) => tag.includes(":"))); // true
console.log(flagOf(fact) === null || typeof flagOf(fact) === "string"); // true
console.log(factsFor(offline, { country: "US", tags: ["sport:baseball"] }).length > 0); // true
```

From the static files, one request for each choice (the indexes are ids only) and then the store files the ids are in (a fact is in one of 100 files by its id):

```js no-run
import { queryFacts } from "@johnmorrisdotca/meigen-sports/load";

const load = { baseUrl: "https://johnmorrisdotca.github.io/meigen-sports/", dataVersion: "0.1.0", fetch };
// The Romanian facts of one calendar day, in every sport:
const romanian = await queryFacts({ country: "RO", day: "03-04" }, load);
// Handball, Romania, the 2000s:
const handball = await queryFacts({ country: "RO", sport: "handball", decade: "2000s" }, load);
```

`loadCountry("RO", load)` is a country's best forty facts, ranked, in one file. `findPeopleByName("gretz", load)` finds a person by first or last name in one small file, and `loadFactsById` loads the facts of the ids it returns.

## What is never a tag

Sex or gender, ethnicity, religion, politics, family and health are not tags, and no field of a fact holds them: the Wikidata dump was filtered before the package saw it, para, wheelchair, deaf and blind sport is left out, and `test/tags.test.ts` fails if a tag's namespace or value says any of those words. A tag for a person's sex would be needed to say a sport is "women's"; the package does not, and a sport is its sport.

## What a tag is not

- A tag is not an identity: two people may share a name, and the Q id (`person:Q…`) tells them apart.
- Teams and people have no country of their own unless the data says one: a club's country is its league's country as the archive holds it (`countryCode`), a person's is Wikidata's.
- `country:` is about the people and the teams of a fact; where an event was held is `host:`, and where a person was born is `birthcountry:`.
- There is no `city:` or `era:` tag: the archive names a venue's city but holds no id for it, and no era is defined in the data. They would be guesses.
