# 文の型

事実は **欄** として保存し、物語は焼き込みません。種類ごとに `src/templates/catalog.ts` の型があり、言語は `en` と `ja` で同じ欄を使います。ライブラリは `render(fact, options)` で文を作ります。静的な JSON には、ライブラリ無しのページ用に既定の一文（`text` / `textJa`）も入れます。

身元は `recordId` と型付きの参照です。無い都市、栄誉、年、存命や死去を型が補いません。

## `render(fact, options)`

| 引数 | 値 | 意味 |
| --- | --- | --- |
| `wording` | `fixed`（既定）、`varied`、`seeded` | `fixed` はその事実の既定の型。`seeded` は使える型の中から選び、同じ種なら同じ文。`varied` も同じ選び方で、**種が必須**（時計も乱数も読みません）。 |
| `seed` | 文字列 | `varied` では必須。`seeded` では省略時に `recordId`。 |
| `templateId` | 文字列 | 指定の型が使えるときだけ。使えなければ `null`（推測しない）。 |
| `locale` | `en` または `ja` | 欄は同じ。型の行が違う。 |
| `asOf` | `YYYY-MM-DD` | 表示している暦日（時計は読みません）。「今日」「この日」と言ってよいかをこれで決め、「何年前の今日」「N歳になる」の起点にもなります。省略すると、どこで読んでも正しい文（日付を全部書き、「今日」とは言わない）になります。 |

戻り値は `{ text, templateId, locale }` か `null`。

## 使えるとき（推測しない）

1. `type` が事実と一致する（誕生日、死去、試合、決勝、記録、賞、初めて、指名、会場、クラブ）。
2. `needs` の欄がすべて空でない。
3. `gate` が存命の状態と一致する:
   - `neutral` — 存命でも死去でも不明でも正しい。誕生日の既定。
   - `deceased` — 出典が死去を述べる。
   - `living` — 出典が存命を述べる。このときだけ「今日N歳になる」を許す。
4. あるときは `when` が勝敗と一致する。

`birthPlace` や栄誉、日の精度が無ければ、それを要する型は使いません。

## その日と、それ以外の日

文は、その事実の日に読まれる場合（10月20日のカードに10月20日の試合が出る）と、それ以外の場所で読まれる場合（ランダムな一覧、チームのフィード、保存された既定の一文）があります。どちらかは `asOf` で決めます。

- **その日:** 事実の月日が `asOf` の月日と同じ。`day: true` の型が使え、「今日」「この日」「何年前の今日」「N歳になる」と言えます。ほかの型は年だけを言います（「…（MLB、1945年）」）。
- **それ以外の日、`asOf` が無いとき:** `day: true` の型は使いません。ほかの型は、記録が持つ精度のままの**完全な日付**を書きます。「1945年7月4日、…」「1960年7月7日に生まれた」「1945年7月」「1945年」「1945年ごろ」。記録が知る以上のことは言いません。月までしか分からない事実は月まで、クラブ名義・賞・指名の1月1日は出典が「その年のいつか」をそう書いたものなので、年だけを言います。

日付を型に入れる欄は四つです。`{dateLead}`（「1945年7月4日、」。その日は空）、`{leadIn}`（同じ。ただしその日は「1945年、」）、`{dateOn}`（「1945年7月4日に」。その日は「1945年に」）、`{date}`（「1945年7月4日」）。`day: true` でない型は必ずこのどれかを含みます。`test/dated-facts.test.ts` は、含まない型と、印が無いのに「今日」と言う型で失敗します。

`dayContext(record, asOf)` は `"onThisDay"` か `"anywhere"` を、`factDate(record, locale)` は記録について文が述べる日付（持っていなければ `null`）を返します。保存する既定の一文（`text` / `textJa`、`captionFromFact`）はどの日にも読まれるので「どこでも」の形、つまり完全な日付です。

## 欠けた値

出典は、値が無いところに「Allegheny Club (none)」のような印を書くことがあります。これは名前の一部ではなく、欠けた値です。`cleanLabel` が、文に使う名前と欄から「(none)」「(null)」「(undefined)」「(n/a)」を取り除きます。印だけの名前は名前として扱わず、穴の開いた文を出すよりは文を出しません。最後の砦として、できあがった文に「(none)」「null」「undefined」「NaN」が残っていれば、その文は返しません。

## 誕生日の言い方

どちらでも正しい既定（クラブ・ポジション・栄誉のいずれかが必要）。

その日だけ（`day: true`）:

- 「Name（クラブ ポジション）はYEAR年のこの日に生まれた。」
- 「今日はName（クラブ ポジション）の誕生日。」
- 「Name（クラブ ポジション）は今日からN年前に生まれた。」
- 「YEAR年のこの日、Nameは場所で生まれた。」

それ以外の日、または `asOf` が無いとき（日付を必ず書く）:

- 「Name（クラブ ポジション）はYEAR年M月D日に生まれた。」（既定）
- 「YEAR年M月D日、Name（クラブ ポジション）が生まれた。」
- 「YEAR年M月D日、Nameは場所で生まれた。」

出典が死去を述べるとき: 「Name（クラブ ポジション）はYEAR年のこの日に生まれた（YEAR年死去）。」（その日）、「Name（クラブ ポジション）はYEAR年M月D日に生まれた（YEAR年死去）。」（それ以外）。代名詞は付けません。名前と年だけの文は出しません。

出典が存命を述べるときだけ: 「Nameは今日N歳になる。」

「N歳になっていた」は使いません。不明は存命ではありません。

## 死去の言い方

クラブ・ポジション・栄誉があるときだけ: `Howie Morenz（Montreal Canadiensのセンター、three-time Stanley Cup winner）が1937年3月8日に34歳で死去した。`（その日なら「1937年のこの日に」）

名前と年だけの文は出しません。無い欄は使いません。クラブ、栄誉、年齢は出典があるときだけです。会場の開場は都市・本拠地・決勝のいずれかが必要です。

## 試合

同じ結果でも型を3つ以上用意します。一方的な大差（その競技の通常の試合に対して）だけ「圧倒した」を使います。サッカーの2対1は圧倒ではありません。その日以外では日付が文頭に付きます: `1900年6月1日、Pittsburgh PiratesがBrooklyn Superbasに10対0で勝利した（MLB）。` その試合の日には日付を省き、年は括弧に残ります。

## ポジション

文にポジションの略号は出しません。記録には略号が残り（`"position": "CF"`）、文では一つの表 `src/templates/positions.ts` で綴ります。表は記録の `sport` で選び、次に略号で引きます。略号の意味は競技ごとに違うからです（Cは野球では捕手、ホッケー・バスケットボール・フットボールではセンター）。綴りは五つのリーグとも北米の通常のもの（英語の center、defenseman）に合わせます。

「Wayne Gretzky（Edmonton Oilersのセンター）は1961年1月26日に生まれた。」その競技の表にない略号は、文に出さず、推測もしません。`test/positions-series.test.ts` は、公開した文に略号が残っているとき、またはデータの略号に表の行がないときに失敗します。

## 決勝

決勝は大会名を書きます。リーグ略号だけ（「1934年MLB」）にはしません。MLBはワールドシリーズ、NHLはスタンレー・カップ、1966年以降のNFLはスーパーボウルです。

勝敗と年とタイトルがある決勝: `1975年5月10日、Montreal Canadiensが1975年のスタンレー・カップでBoston Bruinsに5対3で勝った。`

複数の試合で決まる決勝（ワールドシリーズとNBAファイナル）は、最終戦のスコアをタイトルのように言わず、シリーズの結果を言います。勝敗数はその決勝ラウンド自身の試合から数え、リーグの形式（4勝。1903年と1919〜21年の9戦制ワールドシリーズは5勝）と合うときだけ使います。試合数が合わないシーズン（2008年はアーカイブに重複した試合があります）は、タイトルとして書きません。

`1990年10月20日、Cincinnati Redsが1990年のワールドシリーズでOakland Athleticsに4勝0敗で勝った（第4戦は2対1）。`

どの決勝も、アーカイブが持つ文脈を、その欄があるときだけ足します。決着の試合の会場、そのクラブの何回目の優勝か（そのリーグの優勝者の一覧が完全なときだけ）、優勝チームのレギュラーシーズンの成績（勝・敗、リーグによって引き分けまたは延長負）です。欄: `seriesWinnerWins`、`seriesLoserWins`、`seriesGames`、`venueName`、`venueCity`、`winnerTitleNumber`、`winnerRecord`。

同じ大会・同じ日の「始まった／終わった」は、より詳しい試合があるときは出しません。

選手の紹介は公開されているクラブ名を使います（Alberta Oilers ではなく Edmonton Oilers）。賞の名前をクラブ名に重ねません。

## パッケージが言うすべての文

種類は15あり、どれも英語と日本語で3つ以上の型を持ちます（`TEMPLATE_TYPES`）。`test/patterns.test.ts` は、足りない種類、決して使えない型、同じ型の重複があると失敗します。

- `birthday` 誕生日、`death` 死去、`game` 通常の試合、`final` 決勝、`record` 記録、`award` 賞、`draft` 指名、`venue` 会場、`franchise` クラブの名義、`first` 初めて
- `world-cup-match` ワールドカップの試合、`world-cup-final` ワールドカップ決勝、`competition-start` 大会の開幕、`competition-end` 大会の閉幕、`event-date` 日付のある出来事

チームスポーツのクラブには英語で冠詞を付けます。代表チームとサッカーのクラブには付けません。日本語に冠詞はありません。

### 言葉の置き場

`render.ts`、`run.ts`、`mergeEvents.ts` には文言を書きません。文の形は `src/templates/catalog.ts` の行、そこに差し込む部品（「（延長）」「34歳で」「。…の本拠地」など）は `src/templates/phrases.ts` の行です。部品には言い換えを並べられ、`fixed` は常に最初のものを使うので、公開済みの既定の一文は動きません。三つのファイルに文の言葉が混ざると、テストが失敗します。

### 履歴の行

同梱の履歴の行は、他のコードが読み戻す「データのラベル」として、決まった形の一文（`Brazil 3–1 Chile (World Cup 1950, Group 1).`）を持ちます。`renderHistory(record, options)` はその一文を欄に戻し、上の型で言い直します。引用と未知の一文は `null` を返し、呼び出し側が元の文を使います。

## 並びの中で隣と重ならない

`renderRun(records, { seed, locale, asOf })` は並びを順に言い直します。直前の2つと同じ型は使わず、直前と輪郭（欄を空にした型、`shapeOf`）が違い、最初の文字列（`leadOf`）も違う型を選びます。型が足りなければこの順に条件をゆるめ、隣の文が同じ文字列になることはありません。結果は事実、種、言語、`asOf` だけで決まります。デモの一覧はこれで描きます。

未解決: 公開する事実の一文（`text`、`textJa`）は、いまも `pipeline/convert_extract.py` が自前の文言で書いています。標本5,493件のうち `render` と一致するのは221件で、日本語の区切り文字が違い、決勝に「AFL」と「AFL Championship」の差があり、試合にはシリーズの句が加わります。この文言を型に移し、公開データの一文も型から作るのは 0.5.0 の作業です。

## 型を足す

`src/templates/catalog.ts` に行を足し、`test/templates.test.ts` で存命・死去・不明と欠けた欄を試します。「今日」「この日」「N歳になる」と言う型には `day: true` を付けます。それ以外の型は `{dateLead}`、`{leadIn}`、`{dateOn}`、`{date}` のどれかで日付を書きます。日本語の文は `locale: "ja"` の行だけに書きます。
